# 持有管理工作流 — 还能不能拿（泊松过程与风险管控）

> 前置：已读取 `methodology.md` ＋ 目标标的档案全文。产出＝持有裁定卡（chat）＋档案更新（落盘）。
> 触发方式三种：事件到来（财报／公告／突发）；review clock 到期；用户直接问「X 还能不能拿」。
> 取证：已有档案时默认轻量（增量更新台账）；财报季裁定建议升级为三路并行深研。
> 每次裁定核验后，同步更新 `_Method_Log.md` 裁定追踪记分表（上一条裁定的结果栏）。

## 第 0 步 · 无档案时的两种建档模式

**轻量登记（触发词：「仅登记 X」「登记持仓 X」或用户批量报持仓时）**——不跑深研：
建一份**占位档案**：frontmatter 全字段（status: 持有中，posterior 留空为 0，
frontmatter 加 `stub: true`）＋持仓上下文（成本／数量／币种）＋白话结论节写一句
「已登记持仓，完整裁定待首个检验点或用户询问时补做」＋next_review 设为最近的已知财报日
（查不到则 +30 天）。**不做取证、不设 falsifier、不出裁定**——观测台照常显示行情与盈亏，
裁定章显示「持有·待检验」。批量登记时一次处理全部标的，不逐个分轮。
占位档案的完整补建档在以下时点**懒加载**：首个 next_review 到期、用户问「X 还能不能拿」、
或该标的触发单仓复查线。

## 第 0 步-B · 完整补建档（用户问「还能不能拿」而无档案或仅有占位档案时，硬规则）

用户问「X 还能不能拿」而 TRACK_DIR 无该标的档案时，**禁止直接进入持有裁定**——
没有台账的裁定违反「档案是唯一事实源」硬约束。先按 admission.md 执行补建档全量取证：

1. 排雷扫描（admission 第 1 步，十项红旗）
2. 假设登记（第 2 步：H／¬H／H-0——用户既然持有，追问一句持有理由与成本，登记为 H-0）
3. **三路并行深研取证**（第 4 步默认档：公司财务线／产业链上下游线／竞品叙事线）
4. 后验计算＋三关复核记录（第 5〜6 步，以「补建口径」标注）
5. Falsifier 补注册（第 9 步，标注补注册日期）

台账齐备后才进入下方第 1〜6 步出持有裁定。档案须带「补建档」警示框
（非事前准入、prior 为回溯估计、成本价不参与裁定）。

## 第 1 步 · 事件登记（泊松事件日志）

新信息先入档案「事件日志」：日期／事件／来源。没有新事件也合法——
无事件期的正确动作是核对 falsifier 看板与 λ_event 仪表，**不制造裁定**（无事件期过度行动是首要风险）。

## 第 2 步 · 事件裁定：真跳变 vs 噪音

对每个新事件估 P(真跳变|事件)：
- **真跳变**信号：≥2 个独立通道同时确认（订单＋毛利；指引＋产业链印证）；改写 gₜ 序列或指引中枢
- **噪音**信号：单通道；与旧叙事同源（回声）；无法映射到 H 的验证指标
- 裁定写入事件日志。真跳变 → 进第 3 步更新后验；噪音 → 只记日志，不动裁定，不动 review clock

## 第 3 步 · 贝叶斯更新

- 事件按 LR 分级并入台账，重算 P(H|E)，档案 frontmatter 的 posterior 更新并在「λ_event 仪表历史」留痕。
- 方向自检：这次更新是「后验提高」还是只是「注意力提高」？（媒体热度不是证据。）
- 若出现 LR≥10 级别反向证据（世界观级别打脸），直接跳第 5 步退出信号检查。

## 第 4 步 · λ_event 仪表更新＋事件窗口锚

按资产类型对应的 λ_event 定义（methodology §三.1）给出：上升／平稳／下降 ＋一句依据。
- 上升：催化在变密（多个已排期事件、上修节奏在加快）
- 下降：thesis 进入低反馈期 → 必须同时评估机会成本（现金是选择权；座位每天重新拍卖）
- 同时登记**下一个已排期事件**（财报日／产品节点／交割节点／指数调整）作为事件窗口锚——
  「在等什么」必须有名字和日期，答不出即降级候选

## 第 5 步 · 风险面扫描（每次裁定必跑）

### 5a · 四分诊断（对任何不利变化）
逐项排除，落到四类之一：
1. **价格噪音** → thesis 未伤，可继续等（但不许因此跳过 5b/5c）
2. **证据恶化** → 禁用「长期主义」话术，进退出信号计数
3. **状态迁移失败** → H 被证伪，红色 falsifier 触发
4. **机会成本上升** → 用单位时间期望核对：EV/t ≈ λ_event × P(真跳变|事件) × Payoff − 各项成本；
   λ_event 下降而别处出现高 λ 高赔率座位时，如实写入裁定（四象限对照，methodology §三.6）

### 5b · 退出信号计数板
| 信号 | 判据 | 当前状态 |
|------|------|----------|
| 三信号减仓法 | EPS 一致预期连续下修／供给显性过剩／叙事降级，≥2/3 触发 | |
| 负拐点红线 | Δgₜ ≤ −5pp × 2 季（**市场分流**：A股不独立触发退出，须与三信号／falsifier 并用；海外可独立构成红色信号） | |
| 避雷红线 | 替代价差 <15% 且 NRR 下滑；提价失效 | |
| 金字塔 | 跌破 2 层且 EPS 下修 | |
| Falsifier 看板 | 任一红色条目触发 | |

### 5c · Duration edge 五问（涨了很多、出现「不可持续」念头时必跑）
① D_post − D_mkt 还为正吗　② 利润弹性还在吗　③ 估值迁移到「预支」段了吗
④ convexity 来源换轨了吗（scarcity/backlog/定价权 vs pull-forward/补库存/补贴）
⑤ reference class 该切换了吗
铁律：**「终局不可持续」本身不构成退出依据；「剩余错价消失」才构成。**

### 5c′ · 拥挤度检查（A股标的必跑）
跑 `scripts/sentiment_a.py`，拥挤度读数写入档案并作两处引用：
- **时点段位**：拥挤度「高／极端」＋价格处高位 → 强化「预支段」判定；拥挤度退潮
  （换手分位走低、融资余额缩、龙虎榜降温）→ F6 类预支压力的**缓和材料**
- A股价格行为信号（如「好消息不涨」）与拥挤度联判：拥挤退潮期的阴跌更多是资金面出清，
  证据恶化的权重相应下调（市场适配层：A股价格信号降半级采信）

### 5d · 无记忆性审查
裁定理由里出现「跌久了／等久了／该轮到了」任一变体 → 驳回重写，只接受合法四问。

## 第 6 步 · 持有裁定输出（三选一）

- **高质量等待成立**：λ_event 上升或平稳＋证据在变密＋falsifier 全绿 →
  继续持有语境；写明「在等什么事件」（等待必须有名字）
- **等待质量恶化——降级观察**：λ_event 下降、证据网络稀疏化、或黄色 falsifier 触发 →
  降级语境；写明恢复条件（什么证据回来可升回）与再评估时点
- **退出条件已触发**：红色 falsifier ／三信号 ≥2/3 ／负拐点红线 ／duration edge 消失，
  列明触发了哪几条 → 档案 status 变更由用户确认后执行

**时点段位（每次裁定必标其一，泊松择时输出）**：
跳变前准备窗口／重定价进行中／事件真空期／跳变后消化期——并写明下一个事件锚（名字＋日期）。
加码语境只在两种情形合法：①「跳变前站位」且红色 falsifier 全绿；②LR≥10 超拐点当日
（拐点当天是再定价起点而非兑现点）。事件真空期与消化期一律不给加码语境（无事件期过度行动禁令）。

**输出双视角层（SKILL.md 裁定卡输出规范）**：
- 卡片最前给**白话结论**（三句内零术语：框架怎么看／盯什么（带日期）／什么情况回来重估）；
- 正文后给**个人视角注解**：安全垫现状对路径承受力的影响；补仓上限与资金进出约束下
  还有没有「子弹」。持仓上下文未登记则明示缺口并追问。

裁定卡末尾固定脚注：「本裁定为框架条件状态陈述，不构成投资建议；数据截至〈日期〉。」
更新 next_review：事件锚（下季财报／已排期催化）优先，无锚默认 +30 天；
「降级观察」档案缩短为 +14 天。裁定完成后：档案「0.5 白话结论」节**必须同步改写**（观测台网页读取此节，
过期的白话结论比没有更糟）；「持仓上下文」的安全垫更新；
`_Method_Log.md` 记分表补「裁定时价格」（模拟盘基准）。

## §巡检（触发词：巡检／持仓巡检）

1. 列出 TRACK_DIR 全部档案，按 status 分组（持有中／已准入／观察池）
2. 逐档快检（不做全量更新）：next_review 是否过期／falsifier 看板是否有可立即核验的条目／
   期间是否有已知重大事件未登记
3. 输出巡检摘要表：标的｜status｜posterior｜λ_event｜falsifier 红黄绿｜next_review｜需要动作？
4. 「需要动作」的标的征询用户后逐个走完整持有裁定流程；观察池标的额外检查「等的事件」是否已发生
   （发生了 → 提示可重跑准入门关二关三）

## §复盘（触发词：退出复盘 X）

1. 档案 status → 已退出，补记退出日期与退出时点的关键数据
2. 全周期复盘：入场后验 vs 实际路径；哪些证据裁定对了／错了；falsifier 是否起了作用
3. **错误归因**（methodology §五六类，可多选）＋一句方法修正
4. 写入 `TRACK_DIR/_Method_Log.md`：日期｜标的｜结果概述｜归因分类｜方法修正。
   这是方法本身的贝叶斯闭环——档案可以关闭，方法后验必须留下。


## §左尾预算与价格触发复查（个人视角层，2026-07-28 增设）

背景：falsifier 的采样频率跟着财报走（一季一响），价格却可以在两次财报之间腰斩；
个人投资者承受力的正确单位是**组合冲击**（亏损金额占组合的比例），不是统一回撤百分比——
小仓天然享有更大波动空间。两条线，触发的都是**提前到期的检验义务，不是卖出指令**：

- **单仓复查线**：任一持仓浮亏金额 ≥ 组合总成本的 **3%**（默认，可逐仓覆盖）→
  强制立即重跑该标的持有裁定。价格在此只是 review clock 的触发器——跌得快意味着
  市场可能先看到了我们没看到的东西，值得马上查证，但裁定本身仍走证据流程。
- **组合左尾线**：组合总浮亏 ≥ 总成本的 **10%**（默认）→ 强制全组合巡检＋共同因子复核，
  裁定卡必须回答：左尾预算还剩多少、哪几只在消耗、共同因子是否是主因。
- 触发记录写入对应档案事件日志；观测台账户检查页显示预算使用度。

## §换仓裁定（触发词：「换仓 X→Y」「把 X 换成 Y」）

适用：同主题／同因子内更换持有载体（用户真实操作模式，范例：恒生科技 ETF → 腾讯，
判断单票主导指数且胜率更高——泊松框架的「座位重新拍卖」）。流程：

1. **同源确认**：两者是否共享主因子（β 同源才叫换仓；跨因子＝一卖一买，各走各的流程）
2. **效率比较**（逐项）：胜率结构（集中 vs 分散）｜目标暴露纯度｜费用与流动性｜
   falsifier 可监控性（个股可证伪条件多于 ETF）
3. **裁定输出**：「换仓效率成立／不成立」；目标标的无档案则并行走准入或补建档
4. **双向登记**：换出方档案记减仓/退出与理由，换入方 H-0 登记换仓逻辑
5. 原则：同因子内换仓不重复过关三（总敞口未变）；**若换仓提高集中度，个人视角注解必须标注**
