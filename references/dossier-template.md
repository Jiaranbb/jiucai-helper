# 标的档案模板

> 文件名：`<TICKER> - <名称>.md`，存 TRACK_DIR。frontmatter 是 _Index.md Dataview 看板的数据源，
> 字段名不可改。正文小节顺序固定，方便跨档案对照。引用方法论语料时写篇名
> （档案库与语料库不同仓库，wiki-link 跨库不可跳转）。

```markdown
---
type: 标的档案
ticker: NVDA
name: 英伟达
market: US            # A股 | HK | US
asset_type: AI-receiver   # 财报型 | AI-receiver | 周期 | 软件 | 事件驱动
status: 观察池        # 观察池 | 已准入 | 持有中 | 已退出
horizon: 12-36M
admitted:             # 准入日期，未准入留空
exited:               # 退出日期
prior: 0.35
posterior: 0.35
lambda_event: 平稳    # 上升 | 平稳 | 下降
tri_radar: 0.0        # S* 综合分，未评留 0
certainty_layers: 0   # 确定性金字塔上涨层数 0-5
falsifier_red: 0      # 触发中的红色条目数
falsifier_yellow: 0
next_review: 2026-08-27
last_update: 2026-07-27
tags:
  - 标的档案
---

# <TICKER> — <名称>

## 0 · 一句话状态
〈当前裁定＋在等什么事件〉

## 0.5 · 白话结论（人话版，每次裁定同步更新）
〈三句以内零术语：框架怎么看／盯什么（带日期）／什么情况回来重估。观测台网页读取本节。〉

## 1 · 状态迁移假设
- **H**：〈可证伪表述＋验证指标 m1/m2/m3〉
- **¬H**：〈最强竞争假设〉
- **H-0**（用户原判断）：〈如有〉

## 1.5 · 持仓上下文（个人视角，关三与验证层输入）
| 项 | 值 | 说明 |
|----|----|------|
| 持仓成本 | | 不参与证据裁定，参与关三 |
| 建仓日期 | | 多笔分行记；记不清写约数（如「约 2026-05」），不编造——用于年化口径与建仓时点段位回溯 |
| 当前安全垫 | | （现价−成本）／成本，每次裁定更新 |
| 仓位占组合比 | | 用户口径 |
| 可补资金上限 | | 「还有几发子弹」——个人不能无限补仓 |
| 资金进出计划 | | 已知的流入／流出时点（影响持有路径） |
```

## 附 · 看板种子模板（首次使用时在 TRACK_DIR 生成）

`_Index.md`（需 Obsidian Dataview 插件；无插件时直接浏览档案文件即可）：

```markdown
---
title: 标的跟踪看板
type: MOC
---
# 🎯 标的跟踪看板
> 由 jiucai-helper 维护。本看板与档案均为框架条件状态记录，不构成投资建议。

## 持有中／已准入
（Dataview：FROM 本目录 WHERE type=标的档案 AND status IN 持有中/已准入，
 列：file.link／status／posterior／lambda_event／falsifier_red／next_review，按 next_review 升序）

## 观察池 ／ 已退出 ／ 到期未审
（同上按 status 过滤；到期未审＝next_review < 今天）

→ [[_Method_Log]]
```

`_Method_Log.md`：

```markdown
---
title: 方法后验更新日志
type: 方法日志
---
# 🔁 方法后验更新日志
> 核心循环最后一环。每次退出复盘写一条。归因六类：先验污染／证据权重错误／触发器缺失／
> 仓位过大／右尾识别不足／左尾防护不足。

## 退出复盘
| 日期 | 标的 | 结果概述 | 归因分类 | 方法修正 |
|------|------|----------|----------|----------|

## 裁定追踪记分
> 每张裁定卡＝带日期的可检验预测；检验日逐条记分（✅ 成立／❌ 证伪／◐ 部分）。
| 裁定日 | 标的 | 裁定＋时点段位 | 关键可检验条件 | 检验日 | 结果 | 批注 |
|--------|------|----------------|----------------|--------|------|------|
```
